### Evidence level and phase boundary

I0 tests authenticate exact source bytes, inspect bounded AST/source mechanics, execute current-CDG defect reproductions on synthetic objects, and evaluate independent hand-calculated fixtures. These are **source-bound and synthetic requirement checks**, not real-weight engine execution. `run_i0_group.py` reports their counts separately and leaves BASE-02 mechanically **BLOCKED** while required checkpoint/GGUF evidence bytes or ADR-CDG-020 resolution are absent. The runner first enforces the AutoRound exclusion prerequisite. The evidence manifest must carry exactly the 91 Git-locked artifact IDs, including all 14 explicit absent gate descriptors; every path, size, SHA-256, status, scope tag, kind, and blocker must match its lock identity. The schemas require exactly 91 unique evidence objects and the frozen identity-set digest; the runtime verifier additionally enforces the exact 91 IDs and every locked descriptor field. Thus an undeclared neutral alias, a coordinated lock+manifest addition, or repurposed allowed ID fails before keyword diagnostics. Future inclusion requires a reviewed lock/schema/verifier contract update and an explicit scope/license decision. Real-weight HF → unquantized GGUF → Q8/Q4 numerical parity belongs to **I2 `GRAPH-04`**, not I0.

The four package-oracle classes use a deliberately bounded dependency contract, not an unbounded "all process globals" claim. Each trusted class dictionary and its MRO identities are structurally fingerprinted; unrelated mutable dictionaries/caches owned by base classes are intentionally excluded. Trusted-class methods, the finite source-confirmed inherited selections (`DiffusionGemmaPipeline.register_modules`, `DiffusionGemmaPipeline.progress_bar`, and `DiffusionGemmaForBlockDiffusion.from_pretrained`), closure-held functions, and recursively reached helper functions are dependency-closed by a bounded bytecode data-flow walk. That walk follows global names with builtin fallback, closure cells, receiver/local aliases, attributes/methods, and relevant subscripts; it fingerprints function defaults, closures, globals, selected bound-receiver state, and each resolved endpoint or fails closed for unsupported mutable behavior. Full chains such as `torch.nn.functional.pad` therefore do not rely on a separate alias. Deep mutable traversal is finite and source-derived: `transformers.models.auto.processing_auto.PROCESSOR_MAPPING._extra_content` and the directly iterated `PROCESSOR_MAPPING_NAMES` registry. Direct constructor closure is likewise finite for `DynamicCache`, `StaticCache`, `DiffusionGemmaModel`, and `EntropyBoundSchedulerOutput`. Adding a deep-mutable, inherited-method, or constructor dependency requires an explicit code/test manifest change. Each walk is cycle-safe and fails with `I0-BLOCK-ORACLE-BINDING` at depth 96, 100,000 nodes, 100,000 bytecode states, 20,000 items in one container, 200,000 aggregate container items, 1 MiB for one code object, or 32 MiB of encoded work; string/byte/code and sortable-container limits are checked before copying, encoding, or materializing. Fingerprint stabilization is limited to four passes. Installed oracle source checks require regular no-follow/nonblocking descriptors, the exact captured size and SHA-256, and the 64 MiB source ceiling on both initial capture and every recurring check.

## Source and converter reconciliation

Transformers 5.13.0 is locked at tag commit `6af945f436d85f2b0c5dff9b14feccd27b1d470b`; the previously inspected moving-main model blob is explanatory only because its bytes differ from the tag. Diffusers 0.39.0 is locked at `a3608b512ed7248499a44c61d954965ed9bdae4d`; its entropy scheduler blob is the previously inspected `5382190ec6bf2374bab0932e1f08a0423160a543`. The isolated source-only oracle environment uses the exact wheels and validates installed source hashes. Transformers 5.14.1 is expressly not a substitute.

The selected converter is **DG27 `conversion/diffusion_gemma.py` at `dd0cf04459b0c4f43aa6667dbc0879ac0cd50323`, Git blob `6b85782653bf624c576952e5437928d1b75c145d`, SHA-256 `dbab77e7951b5fd504f21940bee508ff1b868923055a45022910fccbc95a5aaf`**. This choice has three bounded reasons:

1. it is the converter from the exact pin already accepted by ADR-CDG-020, avoiding a second source lineage;
2. its executable tensor mapping is substantively the same as the DG23 candidate for required canvas metadata, encoder scalars, decoder self-conditioning, tied decoder backbone, and text-only vision exclusion; and
3. selection does not promote the donor to an oracle: correctness still proceeds official HF checkpoint → newly generated unquantized GGUF → same-lineage Q8_0 → same-lineage Q4_K_M.

No claim is made that existing remote GGUFs were generated by this converter. Their byte identities and their derivation lineages are separate gate categories. For each BF16/Q8/Q4 output, a prospective binding requires a reviewed Git source change from `UNBOUND` to `BOUND` that pins a derivation ID and the exact record/log IDs, sizes, and SHA-256 values in `reference.lock.json`. A prospective gate requires exactly three bound lineages: all three derivation IDs are globally distinct, all six descriptor IDs are globally distinct, and every descriptor ID is artifact- and role-qualified (`<gguf-id>.derivation-record` or `<gguf-id>.command-log`). Path and inode separation remain independently mandatory. The external evidence store must then provide descriptors and bytes matching those independent anchors exactly. The structured record and log both bind the artifact/derivation IDs, ordered checkpoint and additional inputs, selected converter repository/commit/path/blob/SHA, full command argv/configuration, exact tool repository/revision/source-tree digest/binary size and SHA/build identity/options, quantization parameters, and output ID/size/SHA; the log additionally binds completed status and exit code zero. Fixed envelope objects reject extra keys and all JSON parsing rejects duplicate keys. The record and log cross-bind shared data but do not hash each other, avoiding a circular identity; the Git lock independently hashes both. Coordinated manifest+record+log replacement without a reviewed lock update therefore fails.

## ADR-CDG-020 conflict — explicit future decision required

Selecting the DG27 converter is consistent with ADR-CDG-020's exact accepted pin and does not itself amend the ADR. The broader engine design, however, proposes an owned ordered patch series and full native graph/step capabilities. ADR-CDG-020 explicitly forbids carrying owned patches, bounds maintenance to a SHA plus protocol adapter, and keeps GGUF inference-only-secondary. Those propositions cannot both govern I1 silently.

**Disposition:** `I0-BLOCK-ADR-CDG-020`. Before I1 adopts an owned patch series or capabilities beyond the accepted protocol-bounded secondary path, a separate authorized ADR amendment or supersession must identify the new ownership/maintenance/licensing boundary and update both directions of the supersession record. I0 does not edit the accepted ADR.
